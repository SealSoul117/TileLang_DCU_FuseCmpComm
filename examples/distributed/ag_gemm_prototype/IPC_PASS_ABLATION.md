主要结论：

- **RS：两项优化都重要。** 外提约 3.02～6.84×；在此基础上 half8 再加速约 1.14～2.35×。
  最大尺寸合计约 16.07×，但这是相对当前标量且关闭外提的路径，不是相对最早手写版。
- **AR：两项都有收益。** 外提约 1.32～1.62×；half8 增量约 1.14～1.68×；合计约 1.50～2.71×。
- **AG：未观察到单独外提的稳定性能收益。** 两轮 A/B 都基本持平，不能把千分量级差异解释为收益或回退。
  half8 的增量则约 1.78～2.55×。代码确实命中了外提，但“源码基址外提”并不必然意味着机器码更快；
  本次未做 AG 的 ISA 级归因，不能断言具体原因。
- 所有配置的计时前后全量数值检查通过；独立开关及相关回归 **87 passed**。

### 重复性与解释边界

这里是**真实 JIT 的开关对照**，不是固定 HIP/固定 ISA 的单指令微基准。
前端、算法、调度和编译配置（除两个开关）不变，但现有后端独立编译时仍可能交换 A/B 的 LDS 分配。
已确认 RS8192 的两轮 C11 rank0 HIP 存在这种交换：
首轮 `cp_async_gs_idxen<16, 0>` / `cp_async_gs<16, 32768>`，
次轮对应 `32768` / `0`，LDS 读取偏移同步改变。
因此下表 RS8192 的约 5.9% 轮间差异不能仅归为随机计时噪声，也未证明全部由该布局交换造成。
不要将汇总的六位小数理解为如此精确的纯 PASS 因果效应。

## 对照设置

| 配置 | `tl.enable_dcu_ipc_hoist` | `tl.enable_dcu_ipc_vectorize` | 含义 |
|---|---|---|---|
| A00 | false | false | 标量通信，关闭指针外提 |
| B10 | true | false | 标量通信，仅开启指针外提 |
| C11 | true | true | 指针外提 + half8 向量化 |

这次补充了外提 PASS 的独立开关，省略时仍默认开启；向量化开关沿用现有实现。
不修改两个 PASS 的优化算法，不回滚其它已有优化。特别是 AG 2048 的恒定一次
persistent 循环修复在三组中全部保留。

这是顺序消融：A→B 衡量标量路径的外提收益，B→C 衡量已经外提后的向量化增量收益。
没有测“外提关闭、向量化开启”；向量化 matcher 原本就依赖已外提的标准形式，
因此不能把这组数据解释为两个完全独立因素的四格实验。

## 计时和验证

- Slurm job 10133，dcu0，单节点四张 BW1000 / gfx936，DTK 26.04；8 CPU、64 GiB 内存。
- 每个进程 JIT 编译三种配置，使用不同 kernel 符号避免混淆；三版共用同一份输入、
  同一组 IPC 分配、相同算法、相同 compute/comm 分工。
- 固定 80 Blocks、512 threads/Block、64 KiB LDS、256×256×16 GEMM tile、四级流水。
  每版都查询实际 occupancy，确认整个 persistent grid 能同时驻留。
- 每轮每版 30 次预热、30 次计时；按 A/B/C 的全部六种排列交替启动。
  独立重编译两轮，第二轮反转算子及尺寸的测试顺序。
- 单次先取四个 PE 的 HIP event 耗时最大值；汇总时对两轮合并的 60 个最大值取中位数。
  event 只包围融合 kernel，不含 JIT、分配、上传、flags reset、host MPI barrier、CPU 校验。
- 每个配置计时前后都先 poison 输出，再校验完整中间结果和最终输出。
  RS/AR 检查 local GEMM partial 及集合通信结果；AG 检查完整 gathered A 及 GEMM 输出。
  使用现有全量 dyadic 数值 oracle；不把性能测试当作所有输入分布的正确性证明。
  输入固定，因此缓存完整 CPU 参考结果，避免六次重复 CPU GEMM；每次 device 输出
  仍重新拷回并全量比较。首轮已完成的 RS 2048/4096/8192 使用未缓存 oracle，
  数值检查和 GPU 计时相同。首个未缓存的 RS16384 在计时前中止后重跑，不纳入统计。
- 每个 rank 保存实际 JIT HIP，检查 A00 的 peer 基址位于元素循环内，B10/C11 位于循环外；
  C11 检查 half8 循环及真正的 `uint4` payload 访问，而不只检查 Pass 配置值。
- 计时期间定期检查 `/sys/class/kfd/kfd/proc`；发现非本次四个 rank 的 GPU 进程即中止。
  此检查用于排除可见外部 GPU 任务，不代表锁定时钟或排除全部系统噪声。

## 复现

在已申请的单节点四卡 Slurm 环境中执行：

```bash
cd /public/home/baoboyuan/TileLang_DCU_old
bash examples/distributed/run_ipc_pass_ablation.sh build-old/ipc-ablation-new-run
```

批量脚本自动 source `scripts/dev_old/env.sh`，使用 old 的 Python、源码、build-old 二进制和模板；
不会引用 `TileLang_DCU_develop`。若某组已有四份完整 rank JSON，脚本保留该组并继续未完成项。

单测一个算子/尺寸：

```bash
source scripts/dev_old/env.sh
export OMPI_MCA_pml=ob1 OMPI_MCA_btl=self,vader,tcp OMPI_MCA_coll='^hcoll,ucc'
mpirun -np 4 --oversubscribe --bind-to none --stdin none \
  python examples/distributed/benchmark_ipc_pass_ablation.py \
  --kind ar --size 4096 --warmup 30 --repeats 30 \
  --output build-old/ipc-ablation-single-ar4096
```

`--kind` 为 `rs/ar/ag`；`--size=S` 对 RS/AR 表示 M=N=S、K=S/4，
对 AG 表示 M=K=S、N=S/4。单次启动就测 A00/B10/C11 三版。

完整两轮的统计入口：

```bash
python examples/distributed/summarize_ipc_pass_ablation.py build-old/ipc-ablation-20261014
```

原始记录目录：[ipc-ablation-20261014](../../../build-old/ipc-ablation-20261014/)。
每个 `round*/{rs,ar,ag}S/` 内含四 rank JSON、三版四 rank HIP 和运行日志。

避免把既有独立编译时 LDS 布局变化误判为功能差异；普通 GEMM 验证 Hoist 为恒等变换。

不在 `round*/` 内，因此不参与统计。
